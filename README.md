# 记工时 · 出勤轻松记

一款**纯本地运行**的微信小程序：上班点一下、下班点一下，自动按规则把出勤时长折算成工时，月底一键导出核对。

小程序名称：**出勤轻松记** ｜ 项目代号：`jigongshi` ｜ 版本：`1.0.0`

> 📄 [版权私有声明（非开源）](LICENSE) ｜ 🔒 [用户隐私保护指引](PRIVACY.md)

---

## 它解决什么问题

倒班、工厂、兼职、临时用工的工时统计，通常靠脑子记或纸笔写：一天忘了登记就对不上，月底算总工时更头疼。

本工具把「打卡」压缩成两次点击，其余全部自动完成——按班制规则折算工时、按月汇总、按天核对，需要交班时还能一键复制成可粘贴进 Excel 的文本。

**特点**：纯本地、不联网、无账号、无广告、无第三方 SDK。全部数据只存在你自己的手机里。

## 功能

### 记工时（首页）

- **两种记录方式**
  - **按时间记录**：点「上班打卡」记下当前时间，下班时再点一次，自动算出出勤时长（支持跨零点的夜班，无需手动处理跨天）
  - **按工时记录**：直接手选 1–12 小时，用于补录或临时用工（这类记录不受班制上限限制）
- 页面顶部实时走秒，可随时看到「已经上班多久」
- 未完成打卡状态持久保存，中途退出小程序再回来也不会丢
- 今日记录列表：显示每条记录的班次、起止时间、计入工时与折合工时，可删除

### 月度记录

- **汇总统计**：本月总工时、折合工时、出勤天数、日均工时
- **出勤明细**：整月逐日列出（**倒序，最新一天在最上面**），当天有记录显示工时，无记录显示「无」
- **未来日期不显示**：当月只显示到今天，切到未来月份为空表
- 点任意一天 → 弹出当天明细，可查看每条记录的起止时间，并可**修改**（以新数据重写当天记录）或**补记**（当天原本没有记录时）
- 支持上一月 / 下一月切换与月份选择器

### 历史查询

- **汇总卡**：当月出勤总工时（小时）、折合工时（个）、出勤天数、日均工时
- **近 24 个月**月度统计条形图，数值为**折合工时个数**，点击柱子直接切到该月
- **班次分布**：各班次累计**折合工时个数**对比
- **一键复制**：把当月逐日明细（升序）与合计以制表符分隔的文本复制到剪贴板，可直接粘进 Excel、微信或交给财务；复制内容同时包含出勤小时与折合工时两列

### 其他

- 自定义 tabBar（记工时 / 月度记录 / 历史查询）
- 月度、历史页支持下拉刷新
- 自定义分享标题与封面图（`assets/share-cover.jpg`）

## 工时计算规则（核心）

所有计算集中在 `utils/time.js` 的 `calcWork()`，规则共三条，按顺序生效：

**① 不足 1 小时舍去** —— 出勤时长先向下取整到整小时

| 出勤时长 | 取整后 |
|---|---|
| 40 分钟 | 0 小时 |
| 7 小时 20 分 | 7 小时 |
| 8 小时 0 分 | 8 小时 |

**② 按班制封顶** —— 取整后的时长超过本班制上限时，按上限计入

| 班制 | 上限 | 出勤时长 | 计入工时 |
|---|---|---|---|
| 12 小时班制 | 12 小时 | 12 小时 | 12 小时 |
| 12 小时班制 | 12 小时 | **14 小时 20 分** | **12 小时（封顶）** |
| 8 小时班制 | 8 小时 | 8 小时 30 分 | 8 小时 |
| 8 小时班制 | 8 小时 | **11 小时** | **8 小时（封顶）** |

封顶只影响「计入工时」，**真实出勤时长会完整保留并展示**（记录里同时存有 `minutes` 与 `rawHours`，不会丢数据）。被封顶的记录在今日列表与月度明细里都会标注「已封顶」。

**③ 折算工时** —— 8 小时 = 1 个工时，保留两位小数

| 计入工时 | 折合工时 |
|---|---|
| 4 小时 | 0.50 个 |
| 8 小时 | 1.00 个 |
| 12 小时 | 1.50 个 |

### 两种确认提示

- **出勤不足 1 小时**：折算为 0 工时，保存前会二次确认
- **出勤超过 16 小时**：提示「是否忘记打卡」，建议取消本次上班；若仍要保存，同样按班制上限计入

> 「按工时记录」手选的小时数，以及月度记录里的「修改 / 补记」，属于用户显式录入，**不受班制上限限制**。

### 班制与班次

| 班制 | 说明 | 班次 |
|---|---|---|
| 12 小时班制 | 一天两班倒 | 白班、夜班 |
| 8 小时班制 | 一天三班倒 | 白班、中班、夜班 |

- 首次进入小程序会强制先选班制与班次，之后作为默认值保存，可在首页「变更」随时调整
- 打卡记录的上限按**上班打卡那一刻所属的班制**计算——中途改班制不会影响已生成的记录

## 项目结构

```
jigongshi/
├─ app.js                    应用入口、全局默认班制
├─ app.json                  页面注册、窗口与 tabBar 配置
├─ app.wxss                  全局样式与设计变量
├─ sitemap.json              小程序索引配置

├─ assets/
│  └─ share-cover.jpg        分享封面图
├─ custom-tab-bar/           自定义底部导航（index.js/json/wxml/wxss）
├─ pages/
│  ├─ record/                记工时（首页，打卡 + 手选工时）
│  ├─ month/                 月度记录（汇总 + 逐日明细 + 修改/补记）
│  └─ history/               历史查询（多月统计 + 班次分布 + 复制）
└─ utils/
   ├─ time.js                时间格式化与工时计算（核心规则所在）
   ├─ shift.js               班制 / 班次定义与计酬上限
   ├─ store.js               本地存储封装（记录、配置、未完成打卡）
   └─ ui.js                  toast 与确认弹窗
```

每个页面目录均含 `js / json / wxml / wxss` 四件套。

## 技术实现

- **纯原生开发**：WXML + WXSS + JavaScript，不使用任何框架、组件库或构建工具
- **零依赖**：`package.json` 仅为占位（已标记 `"private": true`，`license` 为 `UNLICENSED`），项目**没有 npm 依赖，也不需要执行「构建 npm」**
- **无后端**：全部数据通过 `wx.*Storage` 存在本机，不发起任何网络请求
- **无第三方 SDK**：不接入统计、广告、推送、登录等任何外部服务
- **分层清晰**：视图在 `pages/`，业务规则集中在 `utils/`，页面只负责展示与交互，便于单独验证计算逻辑

### 本地数据结构

| Storage Key | 内容 |
|---|---|
| `JG_RECORDS` | 全部出勤记录（数组） |
| `JG_CONFIG` | 默认班制与班次 |
| `JG_PENDING` | 已上班、未下班的临时状态 |

单条打卡记录的主要字段：`date` / `endDate` / `shiftType` / `shift` / `mode` / `startTime` / `endTime` / `minutes`（真实出勤分钟）/ `rawHours`（取整后时长）/ `hours`（计入工时）/ `cap` / `capped` / `units` / `crossDay`。

## 本地开发

1. 安装[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)
2. 选择「导入项目」，目录指向本项目根目录
3. AppID 请**填写你自己的小程序 AppID**（仓库内的 AppID 属项目作者，他人无法使用；也可选择测试号调试）
4. 基础库版本 `3.5.5` 及以上（见 `project.config.json` 的 `libVersion`）
5. 直接编译即可运行——无需安装依赖，也无需构建步骤

> 提示：`project.config.json` 的 `packOptions.ignore` 已排除 `.git/`、`.workbuddy/`、文档与系统文件，只影响**预览与上传**的包内容，不影响本地编译。
