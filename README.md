# 记工时 · 出勤轻松记

一款**纯本地运行**的微信小程序：上班点一下、下班点一下，自动按规则把出勤时长折算成工时，月底一键导出核对。

小程序名称：**出勤轻松记** ｜ 项目代号：`jigongshi` ｜ 版本：`1.1.2`

> 📄 [版权私有声明（非开源）](LICENSE) ｜ 🔒 [用户隐私保护指引](PRIVACY.md)

---

## 它解决什么问题

倒班、工厂、兼职、临时用工的工时统计，通常靠脑子记或纸笔写：一天忘了登记就对不上，月底算总工时更头疼。

本工具把「打卡」压缩成两次点击，其余全部自动完成——按班制规则折算工时、按月汇总、按天核对，需要交班时还能一键复制成可粘贴进 Excel 的文本。

**特点**：纯本地、不联网、无账号、无广告、无第三方 SDK。全部数据只存在你自己的手机里；需要换机或备份时，可手动导出/导入 JSON。

## 功能

### 记工时（首页）

- **两种记录方式**
  - **按时间记录**：点「上班打卡」记下当前时间，下班时再点一次，自动算出出勤时长（支持跨零点的夜班，无需手动处理跨天）
  - **按工时记录**：直接手选 1–12 小时，用于补录或临时用工（这类记录不受班制上限限制）
- 页面顶部实时走秒，可随时看到「已经上班多久」；8 小时班制超过 10 小时、12 小时班制超过 14 小时会自动下班并按班制上限记录
- 未完成打卡状态持久保存，中途退出小程序再回来也不会丢
- 今日记录列表：显示每条记录的班次、起止时间、计酬工时与折合工时；**次日仍会显示昨天上班、今天下班的跨天记录**，并标注原日期
- 删除记录后 8 秒内可点「撤销」恢复
- 下班确认弹窗使用点击「下班打卡」这一刻的快照保存，弹窗停留跨过整点也不会改变结果

### 月度记录

- **汇总统计**：本月总工时、折合工时、出勤天数、日均工时
- **出勤明细**：整月逐日列出（**倒序，最新一天在最上面**），当天有记录显示工时，无记录显示「无」
- **未来日期不显示**：当月只显示到今天；不能切到未来月份，「下月」按钮会置灰
- 点任意一天 → 弹出当天明细：
  - **编辑单条记录**：可改班次、上下班时间（按真实时间差重算，自动识别跨天）或按工时记录的小时数
  - **删除单条记录**
  - **补记一条记录**：选班次与小时数，直接写入当天
  - 不再使用「用一天总量重写当天全部记录」的方式，避免多班次记录被合并丢失
- 支持上一月 / 下一月切换与月份选择器
- **月合计口径**：每日工时 ÷ 8 后保留两位小数，再逐日相加；不使用「总工时 ÷ 8」一次性折算

### 历史查询

- **汇总卡**：当月出勤总工时（小时）、折合工时（个）、出勤天数、日均工时
- **近 24 个月**月度统计条形图，数值为**折合工时个数**，点击柱子直接切到该月
- **班次分布**：各班次累计**折合工时个数**对比（只统计当前查询月份，查询 24 个月以外的月份也能正常显示）
- **一键复制**：把当月逐日明细（升序）与合计以制表符分隔的文本复制到剪贴板，可直接粘进 Excel、微信或交给财务；列为「日期 / 班次 / 真实出勤 / 计酬小时 / 折合工时」
- 复制内容会标注封顶、舍去规则，以及「每日折算后逐日相加」的合计口径

### 关于与数据管理

- 首页底部「关于 · 数据管理 · 隐私」进入独立页面
- **导出备份**：把全部记录、默认班制、未完成打卡生成 JSON 并复制到剪贴板，粘贴到备忘录/收藏/电脑保存
- **导入备份**：从剪贴板读取 JSON，覆盖本机数据；导入前二次确认
- **清空记录**：清空全部工时记录与未完成打卡，保留默认班制
- 页内展示版本号、记录条数、有记录月份、隐私说明与版权信息

### 其他

- 自定义 tabBar（记工时 / 月度记录 / 历史查询），使用本地 PNG 图标，不依赖 emoji 字体
- 弹层打开时自动隐藏 tabBar，避免误触到底部导航
- 月度、历史页支持下拉刷新
- 打卡、保存、补记成功时有轻触反馈（部分机型/版本不支持则静默忽略）
- 自定义分享标题与封面图（`assets/share-cover.jpg`）

## 工时计算规则（核心）

所有计算集中在 `utils/time.js` 的 `calcWork()`，规则共三条，按顺序生效：

**① 不足 1 小时舍去** —— 出勤时长先向下取整到整小时

| 出勤时长 | 取整后 |
|---|---|
| 40 分钟 | 0 小时 |
| 7 小时 20 分 | 7 小时 |
| 8 小时 0 分 | 8 小时 |

**② 按班制封顶** —— 取整后的时长超过本班制上限时，按上限计入

| 班制 | 上限 | 出勤时长 | 计入工时 |
|---|---|---|---|
| 12 小时班制 | 12 小时 | 12 小时 | 12 小时 |
| 12 小时班制 | 12 小时 | **14 小时 20 分** | **12 小时（封顶）** |
| 8 小时班制 | 8 小时 | 8 小时 30 分 | 8 小时 |
| 8 小时班制 | 8 小时 | **11 小时** | **8 小时（封顶）** |

封顶只影响「计入工时」，**真实出勤时长会完整保留并展示**（记录里同时存有 `minutes` 与 `rawHours`，不会丢数据）。被封顶的记录在今日列表、月度明细与复制结果中都会标注或说明。

**③ 折算工时** —— 8 小时 = 1 个工时，保留两位小数

| 计入工时 | 折合工时 |
|---|---|
| 4 小时 | 0.50 个 |
| 8 小时 | 1.00 个 |
| 12 小时 | 1.50 个 |

### 确认提示与口径

- **出勤不足 1 小时**：折算为 0 工时，保存前会二次确认；0 工时记录仍算「有记录的一天」，因此会进出勤天数，但不增加总工时
- **自动下班**：8 小时班制超过 10 小时、12 小时班制超过 14 小时，视为忘记下班，自动按 8 / 12 小时补记一条打卡记录；结束时间按「上班时间 + 班制上限」推算，跨天自动标记
- **手动下班超过 16 小时**：仍会提示「是否忘记打卡」，建议取消本次上班；若仍要保存，按班制上限计入。判断使用真实毫秒，16 小时 00 分 01 秒也会提示
- **快照保存**：下班确认弹窗停留跨过整点，保存的仍是点击「下班打卡」时的结果，不会因确认延迟而多算 1 小时
- **班制未知**：旧数据或异常班制按 8 小时保守封顶，避免高估
- **按工时记录 / 月度补记**：属于用户显式录入，不受班制上限限制；**编辑打卡起止时间**则按该记录所属班制的上限重算
- **折合工时合计**：每日工时 ÷ 8 后保留两位小数，再逐日相加得到月合计；不使用「总工时 ÷ 8」一次性折算。
- **出勤天数**：按有记录的自然日计，包含折算为 0 工时的短时出勤；日均 = 总工时 ÷ 出勤天数

### 班制与班次

| 班制 | 说明 | 班次 |
|---|---|---|
| 12 小时班制 | 一天两班倒 | 白班、夜班 |
| 8 小时班制 | 一天三班倒 | 白班、中班、夜班 |

- 首次进入小程序会强制先选班制与班次，之后作为默认值保存，可在首页「变更」随时调整；首次设置完成前 tabBar 保持隐藏
- 打卡记录的上限按**上班打卡那一刻所属的班制**计算——中途改班制不会影响已生成的记录
- 月度编辑单条打卡时，按该记录原本的 `shiftType` 计算上限

## 技术实现

- **纯原生开发**：WXML + WXSS + JavaScript，不使用任何框架、组件库或构建工具
- **零依赖**：项目没有 npm 运行时依赖，也不需要执行「构建 npm」
- **无后端**：全部数据通过 `wx.*Storage` 存在本机，不发起任何网络请求
- **无第三方 SDK**：不接入统计、广告、推送、登录等任何外部服务
- **分层清晰**：视图在 `pages/`，业务规则集中在 `utils/`，页面只负责展示与交互，便于单独验证计算逻辑
- **统一统计口径**：`utils/stats.js` 负责日/月/班次聚合，避免三个页面各算一套

### 本地数据结构

| Storage Key | 内容 |
|---|---|
| `JG_RECORDS` | 全部出勤记录（数组） |
| `JG_CONFIG` | 默认班制与班次 |
| `JG_PENDING` | 已上班、未下班的临时状态 |

单条打卡记录的主要字段：`date` / `endDate` / `shiftType` / `shift` / `mode` / `startTime` / `endTime` / `minutes`（真实出勤分钟）/ `rawHours`（取整后时长）/ `hours`（计酬工时）/ `cap` / `capped` / `units` / `crossDay`。

所有写操作都会返回成功/失败，页面会处理失败提示；Storage 写入失败时不会假装保存成功，也不会在失败时原地改掉内存中的记录数组。

### 备份格式

导出 JSON 顶层字段：

```json
{
  "app": "jigongshi",
  "version": 1,
  "exportedAt": "2026-10-20T12:00:00.000Z",
  "records": [],
  "config": { "shiftType": "12h", "shift": "白班" },
  "pending": null
}
```

导入只接受 `records` 为数组、记录 `date` 为 `YYYY-MM-DD` 的数据；缺省 `id` 会补生成，`hours` / `minutes` 会转为数字。导入会覆盖本机记录、配置与 pending，操作前有二次确认。

## 本地开发

1. 安装[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)
2. 选择「导入项目」，目录指向本项目根目录
3. AppID 请**填写你自己的小程序 AppID**（仓库内的 AppID 属项目作者，他人无法使用；也可选择测试号调试）
4. 基础库版本 `3.5.5` 及以上（见 `project.config.json` 的 `libVersion`）
5. 直接编译即可运行——无需安装依赖，也无需构建步骤

静态检查与回归测试（需要 Node.js 18+，不依赖 npm 包）：

```bash
node tools/check.js
node tools/test-core.js
# 或
npm run check
npm test
```

`test-core.js` 使用 Node stub 模拟 `wx` Storage、`Page`、`getApp` 与 `Date`，覆盖工时边界、存储失败、下班快照、跨天今日记录、月度单条编辑/补记、24 个月外班次分布、备份导入导出等场景。

> 提示：`project.config.json` 的 `packOptions.ignore` 已排除 `.git/`、`.workbuddy/`、`tools/`、`package.json`、文档与系统文件，只影响**预览与上传**的包内容，不影响本地编译。
